# 选题背景与场景需求

## 1. 项目背景

农业种植决策不是单一问答问题。一个可执行的决定同时依赖地块位置、近期天气、土壤条件、作物适宜性、当地农技规则、投入成本、销售价格和农户自身的人力条件。传统经验能够处理熟悉场景，但遇到天气异常、轮作变化、行情波动或多地块管理时，信息收集和比较成本明显上升。

通用聊天模型可以生成看似完整的种植建议，却容易出现三类风险：

1. 把通用作物知识当成特定地块结论，无法说明数据来源。
2. 将价格、产量、成本和风险混成一个不透明的综合分。
3. 回答停在建议层面，没有进入方案、作业记录、实际结果和复盘。

耕策的选题目标是把农业智能体从“会回答”推进到“能完成一条可核验的种植业务链路”。

## 2. 目标用户

| 用户 | 典型规模与条件 | 主要需求 |
| --- | --- | --- |
| 小型家庭农场 | 劳动力有限，地块数量少，投入谨慎 | 控制现金流和风险，减少无效作业，及时获得天气与田间提醒 |
| 大型合作社 | 一个账号管理多个基地和地块，需要统一比较和留档 | 跨地块比较、标准化执行记录、结果汇总、知识复用与权限边界 |

两类用户共用一套地块数据结构，但决策目标不同。系统不替用户选择唯一“最佳作物”，而是分别给出稳收益、低风险、省工易管和养地轮作候选，由用户结合自身条件决定。

## 3. 核心场景

### 3.1 选种决策

用户选择基地和地块后，可以直接询问“这季种什么”。系统读取位置、面积、作物轮作、天气和土壤信息，并结合公开经济估算给出多个目标下的候选排序。用户可以录入当地收购价、预期亩产和现金成本覆盖默认估算。

### 3.2 种植方案

用户采用候选后，系统生成包含整地、播种、水肥、病虫监测、天气应对和收获的任务清单。每项任务包含时间窗口、依据和优先级，可进入农事台账。

### 3.3 执行与结果反馈

用户可以登记计划、完成、跳过和成本，收获后提交实际产量、品质、收入和成本。结果保存在地块历史中，用户反馈进入后续评估。

### 3.4 天气与田间问答

用户可在同一对话框中追问天气预警、施肥窗口、排水、轮作或生育期问题。系统根据问题路由到相应专业 Agent，并持续使用当前地块、方案和作业记录作为上下文。

### 3.5 能力个性化

用户可在能力中心管理 MCP 服务、导入或编辑个人 Skill、建立本地知识库，并把能力绑定到账号、基地或地块。每次运行冻结能力快照，避免历史结果被后续配置悄悄改变。

### 3.6 虫害初筛

用户上传田间图片并补充作物、生育期和受害范围。系统返回候选虫害、可见依据、不确定性和补拍建议。该能力只做初筛，不提供农药处方。

## 4. 功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-01 | 账号管理多基地与地块 | 支持新增、编辑、删除、恢复和地图定位，刷新后数据保留 |
| FR-02 | 地块环境读取 | 按坐标查询天气和公开土壤；失败时明确显示降级状态 |
| FR-03 | 分目标选种 | 四种目标分别排序，展示证据、风险和可覆盖的经济输入 |
| FR-04 | 对话式 Agent 运行 | 流式返回文本，展示专业 Agent、工具、A2A 产物和校验事件 |
| FR-05 | 方案与记录闭环 | 候选可转为方案，可新增作业记录并记录实际成本 |
| FR-06 | 结果与反馈 | 可提交产量、品质、收入、成本和评分，并在地块历史中查看 |
| FR-07 | MCP 管理 | 支持服务发现、工具启停、调用策略、确认与审计 |
| FR-08 | Skills 管理 | 支持系统技能只读、个人技能复制、导入、创建、编辑和发布 |
| FR-09 | 知识库 | 支持 TXT、Markdown、JSON、CSV 导入、分块、检索和作用域绑定 |
| FR-10 | 虫害识别 | 支持 4 MB 内 JPEG、PNG、WebP，返回结构化候选和不确定性 |
| FR-11 | 本地持久化 | 对话、运行、方案、记录、结果、能力快照保存到 SQLite |
| FR-12 | 桌面交付 | Electron 窗口可启动本地服务，支持打包和受限 preload bridge |

## 5. 非功能需求

- **可解释性**：数值由代码计算，结论标注来源、限制和降级信息。
- **可回放性**：每次运行保存有序事件和不可变能力快照。
- **安全边界**：密钥仅在服务端；写操作和破坏性 MCP 工具不能自动执行。
- **弱网可用性**：外部天气和土壤请求失败时保留明确标注的缓存或区域先验。
- **可测试性**：类型检查、自动化测试、构建、浏览器交互和桌面验收均有命令入口。
- **可部署性**：提供本地开发、Docker Compose 和 Windows 桌面打包三种方式。

## 6. 非目标

- 不接入传感器、农机、灌溉或施肥硬件。
- 不承诺产量、收益或市场价格。
- 不用模型替代持证农技人员或农药标签。
- 不在缺少区域证据时声称已完成全国高置信校准。
- 不把演示数据包装成真实客户案例。
