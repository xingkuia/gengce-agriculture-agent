# 项目 Agent Skills

本项目的 Skills 是耕策服务端的农业能力定义，用于约束专业 Agent 的适用场景、证据要求、执行步骤和输出边界。

维护入口：

- `server/skills.ts`：能力目录、版本、逻辑工具名称及输入输出契约。
- `server/skill-guidance.ts`：八个专业的适用场景、所需证据、步骤、追问条件、边界和输出要求。共用规则只维护一份。
- `server/mastra/agents.ts`：在 Mastra 中注册八个专业 Agent，并把技能规则绑定到对应 Agent。
- `server/skill-import.ts`：解析个人技能的 JSON 与 Markdown frontmatter，并执行长度、结构和提示注入检查。
- `server/pest.ts`：视觉请求加载病虫害初筛规则并追加 JSON 契约；最终检查字段与状态的一致性。
- `server/capabilities-store.ts`：把八个内置定义迁移为不可变系统技能，并管理个人副本、草稿、发布版本与作用域绑定。
- `server/mastra/capability-workflow.ts`：每次运行解析技能/MCP/知识库绑定，召回知识并写入不可变 `CapabilitySnapshot`。
- `server/mastra/runtime.ts`：创建 Mastra Runtime，启动选种/问答 Workflow，并桥接现有 SSE 与 SQLite 运行记录。
- `server/mastra/decision-workflow.ts`、`server/mastra/question-workflow.ts`：并行取证、专业 Agent 路由、流式回答、校验与修复。

系统技能不可直接修改。用户可以复制系统技能，也可以从零创建或导入个人技能；三者都会得到 `1.0.0` 草稿并默认绑定到账号。只有发布并绑定到账号、基地或地块后，个人指令才会进入后续运行的快照。当前经济计算、农艺模板及校验仍由代码执行，Skills 描述不会自动赋予新工具能力。模型只承担摘要表达与视觉初筛；本轮冻结的个人技能规则与会话问题相关，知识文本只能作为证据，不能修改系统规则。

个人技能导入支持两种便携格式：

```json
{
  "name": "水稻追肥检查",
  "description": "检查水稻追肥条件",
  "appliesTo": "水稻追肥相关问题",
  "instruction": "先核对天气、墒情和最近一次施肥记录；缺失数据时说明缺口，不得编造数值。",
  "tools": ["weather.get_forecast", "soil.get_properties"]
}
```

```md
---
name: 水稻追肥检查
description: 检查水稻追肥条件
appliesTo: 水稻追肥相关问题
---
先核对天气、墒情和最近一次施肥记录；缺失数据时说明缺口，不得编造数值。
```

单个文件最多 100,000 个字符，技能指令最多 20,000 个字符。导入内容不能要求忽略系统规则、绕过安全校验或索取密钥；保存后仍需运行静态检查并手动发布。

行为验收示例：

| 输入 | 期望行为 |
| --- | --- |
| 这次施肥多少钱 | 路由经济测算，缺少明细则追问，不用全季成本冒充单次费用 |
| 明天下雨还能追肥吗 | 路由农艺，确认阶段、近期操作和天气条件 |
| 土壤 pH 是什么意思 | 路由土壤，保留来源与适用范围 |
| 叶片发黄是不是虫害（未上传图片） | 引导补拍，明确本轮未执行视觉识别 |
| 这张图片不能判断 | 返回 uncertain 和具体补拍要求，不捏造置信百分比 |
| 下季种什么更省工 | 明确目标与播期，不默认处于湖北秋冬播种窗口 |

`pnpm test` 包含意图路由、真实请求体检查（本地模拟模型服务）、视觉状态一致性等回归测试。这些测试不代表农艺正确率或真实病虫害识别准确率。

仍待建设的证据能力包括：统一种植季与农事历史上下文、合规农药登记检索、实地识别评测集和经验证的季末参数校准。缺少这些输入时，当前 Skills 必须说明缺口，不声称已经完成联动或学习。
